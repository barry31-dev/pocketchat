# P1 — shared office workspace

## Implementation contract

Approved input: [chat and office roadmap](../chat-office-roadmap.zh-CN.md), P1,
A01–A06. Baseline: `ab6a035d0493db4786955532d5b5d5eda1efdcdd`.

Goal: continue the same conversations, material snapshots and immutable reports
between the browser and an explicit `office` CLI. Keep the existing CLI/JSONL
formats unchanged. One exclusive workspace writer; an already running browser
service is the only writer and a CLI must authenticate to that same instance.
No automatic server, provider fallback, code execution or general tool access.

Completion checks: roadmap A01–A06, including two-way continuation, request
recovery/stop, isolated drafts, archive/search, backup corruption and old CLI
compatibility. Evidence is recorded below and in the matching review record;
passing an individual checkpoint does not complete P1.

Order and file responsibilities:

1. `office_backup.py`: bounded logical snapshots, integrity and reference
   validation, exclusive-create backup and restore into a new private directory.
   `test_office_backup.py`: real persisted records, invalid formats, links,
   live ownership, corruption and failure preservation (A05).
2. `office_service.py`, `office_web.py`: workspace-bound local discovery and
   authenticated client access without weakening browser origin/CSRF checks.
3. `office_cli.py`, `cli.py`: thin ordinary office commands, explicit send
   confirmation and versioned JSON; no old CLI/session format changes.
4. `office_store.py`, `office.py`, `office_static/`: reuse request/report core;
   add only the daily conversation operations and safe model choice P1 needs.
5. Focused unit/process/browser checks, public command/format/security docs,
   independent deep review, required CI and exact main readback.

Exclusive write scope is the P1 task's enumerated product paths. Do not edit the
shared slice queue or unrelated provider/task engines. No new dependencies.
Stop at an actual ownership conflict, unsafe/unknown external effect, or lost
evidence; preserve a coherent tested checkpoint before context/time exhaustion.
Rollback: revert the new feature commit; never rewrite or delete old workspaces.
No tag, Release, package upload, scheduler change, paid provider or new credential.
