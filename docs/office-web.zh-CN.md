# 本地聊天与办公入口

用户于 2026-11-14 批准：保留并完善聊天，以单 Agent 完成普通办公，增加本地网页入口。
首包为“文本资料→周报→反馈修订→Word 下载→重开继续”。精确契约、限制、权限与实现顺序
唯一维护在 [office-web.md](office-web.md)；本页是中文使用导航，不另维护交付状态。

安装源码可选依赖后运行：

```bash
python -m pip install '.[office]'
pocketchat web --config ./pocketchat.json --data-dir ~/.pocketchat/office
```

打开终端打印的私有链接。链接片段含本次服务令牌，不要转发；服务重启后旧令牌失效。
普通聊天直接输入；需要报告时点击 Create report。Add material 只接受 TXT/Markdown/CSV，
每份最多 12 KiB，一次最多八份、合计 48 KiB；当前模型上下文上限可能要求更少资料。
上传只复制到本地；发送前确认框明确披露会话、当前选择和相关历史将传给所显示模型端点。

完成后可预览、下载 Markdown/Word，或选择某一版本继续修订。旧版本不覆盖。停止操作先显示
Stopping，只有运行线程真正退出才释放工作槽；重启发现未完运行会显示 unknown，不自动再请求。
重试之前回看错误和已有成果；网络回执未知不意味着原请求未执行。

这是同一用户的本地入口，不是公网服务器或同账号恶意进程的沙箱。没有自由 shell、复杂代码
执行、多 Agent、定时任务、PDF/DOCX 输入、OCR、Excel/PPT 输出或账号云同步。
真实模型事实质量、Word 分页和跨平台体验要分别验证，离线桩不能代替。

## P1 基础接续：从 CLI 操作同一工作区

新增 [office CLI](cli.zh-CN.md)，可访问网页服务里的同一会话、资料与指定报告版本。
CLI 使用私有、工作区绑定的独立 bearer 发现记录；不放宽网页 cookie、Origin 或 CSRF。
所有权未知／失联时拒绝，不自动启动第二写入者。备份通过当前写入者取得，恢复只到新目录；
其[数据范围与排除项](formats.zh-CN.md#office-数据备份-v1)必须区分于完整目录归档。

这仍**不是 P1 整包完成**。本次接入既有模型配置选择及交互式办公入口；编辑／重新生成见下节；整包验收仍须单独核对。
报告／修订与网页回执恢复沿用已有实现，不重复构造业务内核。

## 日常会话

搜索同时覆盖标题和消息正文；点击正文命中项打开会话并聚焦实际保存的消息。结果最多 100 条，
以纯文本展示；**Archived conversations** 同时切换列表与搜索范围。**Archive / Restore**
只归档/恢复，不删除内容；归档时仍可查看、导出指定版本，新发送/改名/导入前需先恢复。
旧工作区显示 **Back up & upgrade**，先在私有目录保存并回读备份，再从 schema 2/3 升至 schema 4。

未发送草稿（正文、报告开关、资料选择、前序版本）保存在本浏览器页签，按工作区和会话隔离，
新会话有单独草稿。切换/刷新恢复对应草稿，但不会恢复发送同意，也不会自动发送。关闭页签
可能丢失草稿；它不是 CLI 草稿，不进入数据库备份或已发送历史。待恢复请求使用另一份
工作区绑定记录，刷新只提示恢复，不重放。

编辑草稿会撤销发送确认。上传、归档、改名与新会话创建持有短期界面动作锁，延迟响应不覆盖
另一会话的输入框；发送在异步创建之前快照内容，返回后若草稿或确认变了则拒绝发送。
旧版未绑定工作区的标签页回执会显示 **Check saved receipt**：只读取并核对当前工作区的
已存请求，不重放。未找到或内容不匹配仍阻止新发送；确认放弃仅删除标签页记录，不删除服务端请求。


### 既有模型配置选择

页头只列当前写入者加载的 profile，不自动测试联网或消耗模型调用。选择只影响新请求，
在飞线程退出前拒绝切换。所有新请求记录模型／端点；切换撤销网页确认，其他客户端改变
显示中的模型或端点时，本次发送拒绝并要求重新确认。服务器内容绑定哈希还会拒绝
preview 与 send 之间的变化。旧回执恢复不替换模型，不再次调用。


## 保留历史的聊天分支

对已完成的普通聊天问题点 **Edit question**，或对回复点 **Regenerate**，原问题会成为
未发送草稿；修改后发送是编辑，不改正文发送是重新生成。选择动作本身不调用模型，发送前
先点 **Review branch** 查看将实际发送的历史前缀及正文/资料；这一步不调用模型，随后
才可勾选同意发送。草稿、模型或上下文变化须重新预览确认。**Continue current branch instead** 取消分支选择、保留草稿正文。

新回复成功后，当前上下文只包含所选轮次原先的前缀和新回复，不混入旧回复及其后续消息。
旧内容保留在 **Saved earlier branches**，可展开、复制和搜索定位，但不作为当前历史发送。
失败、取消或中断的请求不切换当前路径；重新打开仍保留路径。分支草稿按页签保存，刷新不恢复同意。

报告继续用 **Revise** 与指定版本导出，不走普通聊天重新生成。资料引用标签保持会话级稳定，
旧报告不因聊天路径变化而丢失。CLI 使用同一服务、回执与确认；见 [CLI 文档](cli.zh-CN.md)。
分支需要 schema 4；旧目录先显式备份升级。回退应把升级前备份恢复到新目录，不能手改版本号让旧程序读取。

### 键盘与长对话

Tab / Shift+Tab 在原生控件之间移动，空格切换发送确认，Enter 激活当前聚焦的
发送、停止或重试按钮。消息输入框中的 Enter 只换行，不发送。原生文件输入聚焦时，
「Add material」标签显示焦点框。搜索结果可用 Enter 打开并把焦点移到原消息；
切换会话或刷新仍保留本标签页的未发送草稿。

网页打开／重新打开会话后可看到 CLI 发起的请求。任一端均可停止同一个运行；
`stopping` 不代表完成，重试必须等最终回执后重新审阅并确认。停止后的输出不会
追加成已完成消息或报告。

现有浏览器验收入口新增 `OFFICE_REMAINING_ONLY=1` 模式；把 `OFFICE_OUTPUT`
设为新的私有证据目录，`OFFICE_PYTHON` 指向兼容解释器，在具备 Playwright 与
Chrome 的环境运行 `node tests/office_p1_browser.cjs`。该模式只核本包剩余路径：
200 个预置轮次（400 条消息）、两次可控本地请求、键盘／搜索／草稿与双向停止；
不重复报告和分支流程，也不构成性能基准、真实模型或完整无障碍验证。

改用 `OFFICE_REVERSE_EXPORT_ONLY=1` 可只跑 A01 反向缺口：网页导入两份资料 →
网页初稿 → CLI 修订 → 网页分别下载旧／新版 Markdown 与 Word，逐版核正文和来源，
并用 python-docx 读回。两个模式都用新建本地 fixture，不访问真实账号。
