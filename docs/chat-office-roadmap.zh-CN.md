# PocketChat 网页版与 CLI 基础办公扩展方案

> **版本：v1.0 · 规划日期：2026-11-14。**
> **定位：产品规划，不是功能已实现、已验证或正式发布的声明。**
> 用户已明确后续方向：完善网页版与 CLI 的聊天和普通办公基础功能，不做多智能体和编程。
> 本次交付仅为方案；下面的开发包是实施顺序，不是已经领取、启动或完成的任务。

**目标**：让用户用网页或终端完成“聊天 → 选择资料 → 理解内容 → 生成文档 → 修订 → 导出 → 重开继续”。

**架构**：两个正式入口共用一套办公业务能力和工作区；复用既有聊天、模型适配、请求回执与版本机制，不重新搭建通用智能体平台。旧 CLI 与历史会话保持兼容。

**技术基线**：现有 Python 应用、本地 SQLite 办公工作区、轻量 HTML/CSS/JavaScript 网页及可选 Word 导出依赖。新增格式能力保持可选，不使普通聊天必须安装整套办公依赖。

**维护边界**：本文是本次扩展的详细规划唯一来源；实际任务契约见 [slice queue](slice-queue.md) 或其引用 issue，首包现有实现契约见 [office-web.md](office-web.md)，发布状态只见 [release ledger](release-ledger.md)。不在本文复制实时任务、租约或发布状态。

## 1. 现有基线与真实缺口

“已有”指该提交存在相应实现，不代表本次规划重新运行验证；首包运行与审查证据见 [原审查记录](review-office-web-v1.json)。

| 格式 | Word 导出支持基本标题、项目符号和加粗 | 普通文档阅读、复杂一点的文档结构及基础表格处理 |

当前文本限制仍以 [office-web.md](office-web.md) 为准：每份 12 KiB、最多八份、合计 48 KiB，并受模型上下文约束。后续不能仅放大上传限制就宣称支持长文档。

## 2. 产品原则与成功标准

### 2.1 六条原则

1. **聊天优先**：普通问题直接问答，不先创建任务、计划或工作流。
2. **两端同等支持**：网页适合阅读和整理，CLI 适合键盘操作与显式批处理；同一项办公能力不只做网页按钮。
3. **本地优先、发送透明**：资料先留在本地；发送哪些内容、发给哪个模型端点，在请求前明确展示。外部模型调用不是离线处理。
4. **结果可接续**：会话、资料快照、文档版本和运行回执有稳定身份，切换入口不丢上下文或另造同名副本。
5. **操作可解释、重要数据可恢复**：不静默覆盖、裁剪、重试、迁移、删除或更换模型；迁移前先具备备份和恢复。
6. **轻量且有边界**：不引入多模型投票、多智能体调度、任意代码执行、向量数据库或常驻后台任务来完成基础办公。

### 2.2 用完整用户结果衡量，不按模块数计完成

- 新用户按说明完成已有模型配置后，能从任一入口开始聊天，不需要理解内部任务格式。
- 同一工作区内，终端生成初稿、网页修订、终端导出指定版本可以接续；反向路径也成立。
- 文档问答能回到实际输入的原文位置；缺失信息明确标注，而不是补造答案。
- 导出文件内容、版本与来源匹配，实际打开后可使用；文件存在、下载成功和排版合格分别验证。
- 请求失败或断连时能判断“失败、仍运行、已完成、结果未知”，不会因界面重试无意重复执行。

## 3. 功能边界：做什么，不做什么

### 3.1 当前扩展范围

普通聊天、会话管理、显式资料选择、文档阅读与问答、摘要与写作、版本修订、常用文件导出、基础表格处理、配置诊断、备份恢复和本地数据管理。

写作覆盖邮件草稿、周报、会议纪要、项目报告、方案说明等日常文本；提供草稿和下载，不代用户发送邮件、消息或上传到第三方平台。

### 3.2 明确排除

- 多智能体、委派、自动规划、自动分工、模型竞赛和自动选优。
- 编程助手、代码修复、代码仓库管理、自由 shell、模型生成脚本后执行。
- 定时自主运行、后台批处理服务、账号体系、云同步、团队协作和远程服务。
- 扫描件 OCR、语音/视频、自动联网检索、云盘/邮箱连接器和插件市场。
- Office 宏、任意公式引擎、复杂排版还原、完整 Excel 或 PowerPoint 替代品。

PPT 大纲与基础 PPTX 导出只列为后续候选，不进入本方案四包的验收或开发排期。扫描件、联网能力和多模态也不能借“基础功能”名义附带进入。

既有高级或历史命令不在本轮删除，但不再作为新办公入口的推荐路径。隐藏旧功能不等于移除了其实现；后续废弃必须遵守 [兼容约定](compatibility.md)，不能删除历史用户数据。

## 4. 网页版与 CLI 的操作设计

### 4.1 网页版：围绕会话、资料和成果

保持“左侧会话、中央聊天、右侧资料与成果”的现有结构，不改造成流程图或任务看板。

- **会话区**：最近会话、改名、标题/正文搜索、命中定位、归档与恢复。归档可逆，不冒充删除。
- **聊天区**：清晰的流式状态、停止、失败说明、复制、草稿恢复、编辑后另存续聊和重新生成。阅读旧消息时不强制滚回底部。
- **资料区**：查看原文或抽取结果、来源名称、大小、选中范围和本次实际发送清单；后续增加页码/段落定位。
- **成果区**：文档标题、版本、生成来源、修订差异、预览与下载。修订失败不产生一个看似完成的新版本。
- **设置与帮助**：工作区位置、已有模型配置、诊断结果、备份恢复及格式支持说明。只显示脱敏端点，不显示或回传密钥。

键盘焦点、对话框操作、状态可读性、窄窗口和长内容布局随功能验收；响应式网页不等于手机原生应用或已验证的移动设备体验。

沿用现行语言规范：产品界面、命令和代码使用英文，保留中文使用说明。中文 UI 本地化不是本方案暗中修改的既有规则。

### 4.2 CLI：直接完成办公，不要求写任务规格

保留现有命令；建议新增统一的 `office` 命名空间承载共享办公工作区，不改变旧 `chat`、`run`、`agent`、会话 JSONL 或已有 JSON 输出契约。

**以下是拟定交互，不是当前可运行命令。** 参数最终随首个实施切片写入 [CLI 手册](cli.md) 和 [格式说明](formats.md)，不能把本节当成已发布帮助。

```text
pocketchat office --data-dir PRIVATE_DIR chat
pocketchat office --data-dir PRIVATE_DIR conversations list
pocketchat office --data-dir PRIVATE_DIR materials add --conversation ID --file notes.md
pocketchat office --data-dir PRIVATE_DIR report create --conversation ID --prompt "Draft a weekly report"
pocketchat office --data-dir PRIVATE_DIR report revise --conversation ID --version VERSION_ID --prompt "Shorten the risks section"
pocketchat office --data-dir PRIVATE_DIR export --conversation ID --version VERSION_ID --format docx --out report.docx
```

交互模式提供会话/资料/版本选择和发送确认；单次命令支持明确的输入输出。非交互调用必须显式确认绑定的请求内容，不能把管道输入或通用 `--yes` 当作无限文件读取、发送或覆盖授权。

新命令支持稳定、带版本的结构化输出；与人类输出共用一份业务结果。错误、退出码、stdout/stderr 规则按既有 CLI 约定登记，不将进度文本混进最终 JSON，也不改变旧命令的输出。

### 4.3 模型配置与发送确认

复用现有 profile 管理和诊断，不另造模型目录或自动选择系统。网页/新 CLI 可以选择已有配置，并显示当前模型、端点及可用能力；能力不支持时明确拒绝或关闭对应控件。

连接测试由用户显式发起，并说明会联网；不得为了打开设置页自动消耗模型调用。密钥不进入日志、URL、命令历史、备份包或可复制诊断。

模型切换只影响新请求，不改写旧请求记录。在飞请求不切换；切换或资料范围变化使旧发送确认失效。重试不自动换端点。用量区分实际返回、估算和未记录，不编造费用。

## 5. 四个开发包与验收出口

四包顺序是 **P1 → P2 → P3 → P4**。包内允许多个提交和检查点，但只有用户路径和负例都成立才算整包完成。不开四条并行产品主线，不按日历承诺未经评估的交付日期。

### P1：双端日常聊天与办公接续

**用户结果**：同一份会话、资料和报告能在终端与网页之间继续处理。

**必做范围**：共享办公服务入口；CLI 普通聊天/资料/报告/修订/导出；网页正文搜索与定位、归档/恢复、草稿恢复、已配置模型切换；现有停止/回执/版本机制双端一致；工作区备份与恢复。补齐错误说明、键盘操作和长对话基本体验。

**包内顺序**：

1. 固定工作区、会话、来源、运行、文档版本的共享契约；把旧 CLI 兼容边界写清。
2. 在任何存储升级前完成一致性备份、校验、恢复到新目录和失败保全。
3. 打通服务内复用与单一写入者，先让两端读取同一结果、控制同一请求。
4. 增加易用 CLI 办公入口，复用现有报告与 Word 导出，不经过历史 TaskPlan 编排。
5. 补齐网页日常会话操作；编辑问题/重新生成保留原回复及后续历史，不制造矛盾上下文。
6. 跑双向接续和异常路径，再交付文档与相称审查记录。

**验收用例**：

- `A01`：CLI 导入两份文本资料、生成初稿；网页打开同一会话修订；CLI 导出指定旧版和新版，内容及来源可区分。反向流程同样验证。
- `A02`：正文搜索可定位到命中消息；归档后可恢复；切换会话、刷新页面或重开交互入口时，未发送草稿不会被误发送或串到另一会话。
- `A03`：任一入口停止请求，另一入口显示同一状态；工作线程退出前不释放执行槽。
- `A04`：丢失发送回执后恢复原请求；同 ID/同内容不重复调用，同 ID/不同内容拒绝；未知状态不自动重放。
- `A05`：备份恢复到新目录后，会话、资料、文档版本与关键引用一致；坏备份和未知版本拒绝，原目录不变。
- `A06`：旧 CLI 的代表性会话、搜索和导出契约仍成立；办公入口不会因旧 profile 启用工具而获得代码执行、委派或任意文件写权限。

**不含**：PDF/DOCX 输入、XLSX、PDF 导出和大范围界面重做。P1 不以这些后续能力未完成为由延迟双端基础闭环。

### P2：普通文档阅读与来源问答

**用户结果**：两端都能读取普通 PDF/DOCX，围绕选中内容问答并回到原文依据。

**必做范围**：文本型 PDF、DOCX 正文/常见表格抽取；抽取预览；按文件/页/段落选择范围；摘要、问答、要点提取和多资料对照。原始文件摘要与抽取结果摘要分别保留，并记录抽取器版本和缺失范围。

不承诺还原复杂排版。PDF 用页码和抽取片段定位，DOCX 用段落/表格定位，不捏造尚未排版的 DOCX 页码。来源材料是数据，不是指令或权限。

分别限制原文件、页数、解压规模、抽取字符和发送预算；实施前用代表性样本确定并公开限额。超限时展示可选择范围或明确拒绝，不能静默裁剪、无限载入或把一次未超限外推为任意大文件安全。

**验收用例**：

- `A07`：同一份文本 PDF 和 DOCX 在两端得到一致的来源身份；摘要和问答引用能定位到实际抽取内容，选中范围之外的内容不声称已经读取。
- `A08`：扫描件、加密文件、损坏文件、伪装扩展名、压缩炸弹风险、超限与外部关系均有明确拒绝或部分读取说明；不执行宏、嵌入对象或自动抓取链接。
- `A09`：原文件发生变化后，旧报告仍指向旧快照；新的读取生成新来源版本，不能替换旧引用。

**不含**：OCR、云端解析、大型知识库、自动抓取网页、完整 Office 文档结构往返编辑。

### P3：文档写作、修订与可用交付

**用户结果**：基于资料形成常用文档，按反馈修订，下载可阅读、可编辑的成果。

**必做范围**：邮件草稿、周报、会议纪要、项目报告、方案说明五类轻量模板；标题/受众/语气/结构选择；指定段落修订、版本差异和来源继承；Word 标题、编号、列表、表格及页眉页脚；PDF 导出；本地成果管理与明确的数据清理入口。

模板是内置写作结构和提示，不是技能插件或自动执行流程。会议纪要只处理用户给出的文字记录，不增加音频转录。缺少时间、责任人、结论或数字时明确留缺口。

预览与导出共用规范化文档内容。PDF 转换采用明确的可选本地后端；具体依赖在本包格式方案中核验许可、平台支持和安装成本后选定，不调用模型生成的命令或自动安装运行环境。

**验收用例**：

- `A10`：五类模板各有代表性资料；首稿及两轮修订保留历史，指定段落修改不无意删除其它章节，差异与实际内容一致。
- `A11`：Markdown、Word、PDF 都绑定指定文档版本；中英文、长段落、编号和跨页表格实际打开并渲染检查。无法满足页数目标时明确说明，不能把“一页”提示当实测分页。
- `A12`：清理前展示对象、关联资料/请求记录和影响范围；在飞或引用冲突时拒绝。归档、删除和安全擦除区分说明，外部导出与旧备份不会被伪称已一并删除。

**不含**：所见即所得的完整 Word 编辑器、像素级模板复刻、自动对外发送、电子签章和合同合规判断。

### P4：基础表格阅读、整理与报告引用

**用户结果**：从 CSV/XLSX 中筛选整理数据、得到可核对的统计结果，并导出或写进报告。

**必做范围**：表/列预览、显式选择工作表和范围、筛选、排序、去重、分组计数/求和/平均、简单柱状/折线图、CSV/XLSX 输出和报告插入。

计算由固定、可测试的程序完成，模型只负责解释或提出结构化操作建议；用户确认后只执行预设操作，不生成或执行 Python/SQL/宏。重复运行同一输入和操作应得到相同数据结果。

导入不计算未知公式；既有缓存值若采用，必须标为未重新计算，缺缓存不能猜值。首版导出优先为值型表格，不承担任意公式重算。文字单元格的公式注入防护不能把合法数值悄悄改成字符串。

**验收用例**：

- `A13`：已知结果的数据集覆盖空值、日期、重复行和混合类型；筛选、统计、图表底层数据和导出结果一致，原始文件不变。
- `A14`：相同来源版本和操作在两端产生一致结果；CSV 编码、XLSX 工作表/范围及异常公式明确处理；导出防公式注入，未知或不支持的类型不静默强转。

**不含**：大型数据分析平台、任意函数库、宏、复杂透视建模、外部数据自动刷新或 PPTX 输出。

## 6. 共享架构与数据契约

### 6.1 选择一个共享业务层，而不是两个产品

保留现有 `Session` 与 provider 适配。办公业务层承接会话、资料、请求、文档和导出；网页适配器及 CLI 适配器只负责输入、确认和呈现。不得复制两份报告逻辑或分别定义成功状态。

| 对象 | 共同契约 |
|---|---|
| 工作区 | 本地私有目录、明确版本、单一写入者；备份不包含密钥 |
| 会话 | 稳定 ID、名称和归档状态；两端使用同一身份 |
| 草稿 | 与会话及入口绑定；与已发送消息、未知请求的恢复数据分开 |
| 资料快照 | 不可变内容及摘要；后续格式保留原始与抽取身份、定位和限额信息 |
| 请求 | 内容绑定的 request ID、模型/发送范围快照、状态与回执；重试不混同恢复 |
| 文档版本 | 不可变版本 ID、前序版本与来源依赖；失败输出不能晋升为完成版本 |
| 导出物 | 绑定版本/格式/输出摘要；生成成功、写入成功、可阅读分别判断 |

### 6.2 单一写入者与双端接续

当前办公工作区已有进程级独占锁，不能仅让两个进程直接打开同一数据库就声称共享完成。

网页服务运行时，新 CLI 通过其受认证的 loopback 服务操作同一业务实例；没有服务时，CLI 可独占打开工作区并在退出时释放。连接失败、端点身份不匹配或所有权未知时拒绝，不强抢锁或悄悄启动第二个写者。

为 CLI 增加的认证和服务发现必须单独验收：发现文件不是发送授权，端点需绑定工作区身份；会话令牌不能进入 URL 查询、命令历史或诊断。不得为 CLI 放开公网监听、绕过网页现有 origin/CSRF 保护或接受任意浏览器提供的宿主路径。

同一工作区仍只执行一个模型请求；切换入口不增加并发权限。服务由用户显式启动，不随系统后台常驻，不扩大成远程 API 产品。

### 6.3 旧 CLI 和存储升级

旧会话格式、命令与导出继续使用原有路径。新 `office` 入口不自动接管旧 JSONL，不按名称猜测应当合并哪两段会话。旧会话向办公区导入先保留为兼容性候选，只有显式映射、预览和验证后才能实现。

办公工作区升级必须有版本识别、一致性备份、迁移前检查和失败恢复；不复制运行中的 SQLite 文件及 WAL 来冒充完整备份。先恢复到新目录验证，旧目录保留；未知版本拒绝，不自动降级或清空数据库。

## 7. 隐私、安全与可靠性要求

这些随所在开发包交付，不单列一个遥远的“安全阶段”。

- **发送范围**：展示当前问题、相关历史、资料片段和所选模型；撤销资料选择只改变未来请求，不承诺撤回已发送内容。
- **输入隔离**：资料、模型回复和导入元数据不能变成宿主命令、HTML 脚本、权限或可执行 Office 内容。
- **写入范围**：资料复制进入专用工作区；导出到显式选择的目标，新文件优先；覆盖需确认准确目标，不能覆盖源码、凭据或任意隐藏路径。
- **恢复语义**：网络断连不等于请求未执行；恢复先查原回执。只有明确的新操作才产生新的 request ID。
- **停止语义**：停止请求先进入 stopping；线程实际退出后才释放槽位，旧回执保留真实终态。
- **数据清理**：区分归档、删除、备份、外部导出和安全擦除；仅处理明确列出的自有数据，不承诺磁盘物理擦除或远端撤回。
- **资源边界**：限额和超限说明是产品能力的一部分；格式解析、渲染和模型请求不无限并发。没有当次测量就不声称低内存环境安全。
- **诊断**：错误信息可操作、可复制且脱敏；不得把密钥、令牌、原始敏感资料或私人路径不加筛选地写入报告。

## 8. 验证与交付方式

### 8.1 分层验证，不拿一种证据替代另一种

1. **契约与确定性逻辑**：针对共享身份、状态机、锁、来源引用、迁移、解析拒绝和统计结果写判别性测试；不为纯样式或文本变化添加镜像测试。
2. **真实文件/进程**：读取实际文件、生成输出、重启、恢复和所有权竞争；测试 provider 只证明接线，不证明模型质量。
3. **网页＋终端用户路径**：按 A01–A14 所属包实际操作，两端不能只测服务层；记录使用的平台、终端和浏览器。
4. **格式可用性**：Word/PDF/XLSX 分别打开、解析和按需要渲染；未知公式、缺字体或布局损失单独记录。
5. **真实模型内容质量**：使用已有且获准的配置，以合成/自有资料验证准确性、引用支持、遗漏和修订保持；不新增付费凭据，也不将流畅度当事实正确率。
6. **准确候选交付**：按既有流程完成对应审查、必要 CI 与 main 回读；不重复无新改动的已绿判据，不因此自动创建 tag/Release 或上传安装包。

### 8.2 每包留下的证据

记录实际候选、样本、命令/工具版本、结果、失败与未验证范围。P1 留两端接续和恢复证据；P2 留抽取与定位样本；P3 留实际导出及渲染检查；P4 留可独立算出的输入输出对照。

不设“所有测试绿所以用户问题已解决”的出口。完整用户路径、异常行为、文档说明和外部回读均覆盖后，才能登记相应开发结果；发布仍单独遵守现有流程。

## 10. 风险与取舍

| 风险 | 本方案的取舍 | 进入下一步前应看到什么 |
|---|---|---|
| 两端各造一套而数据分裂 | 共用业务层和工作区；旧 CLI 保持原契约 | A01 双向接续与同一 ID/版本 |
| 为了共享数据绕过进程锁 | 单一写入者，连接或独占二选一 | 所有权竞争、失联、恢复的负例 |
